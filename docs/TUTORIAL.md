# Guided rotor-balancing lab

The floating guide teaches a complete **two-plane rotor-balancing experiment** through physical work at the station. It begins with the problem: a tiny mass away from the rotation axis produces a rotating force, which makes the supporting structure vibrate. The learner measures that vibration, deliberately changes the rotor with known test masses, predicts correction weights, then checks the prediction with fresh measurements.

No prior balancing knowledge is assumed. Thirty-eight short steps introduce one task and its reason at a time. The learner uses the real micrometer, Mass and Angle dials, guard, and console caps; these are experiments with observable outcomes rather than a menu tour. A small label and arrow mark the current target. Bundled speech supplies the explanation without covering the station with paragraphs.

A typical first run takes about 10–15 minutes, depending on how much narration and observation the learner chooses. The guide can be paused, skipped, restarted, or disabled at startup. All motors, measurements, and faults are synthetic. Guide completion does not certify operator competence or machinery safety.

## Learning path

| Steps | Physical activity | What the learner discovers |
| --- | --- | --- |
| 1–4: Meet and reference | Seat the tray rotor, press **HOME**, use the right stick to reach the actual micrometer on the station's right side, turn it at least 0.10 mm and release, then **HOME** again. | Off-axis mass produces a rotating force. A non-contact sensor needs repeatable geometry. The drum moves the probe 0.5 mm per revolution; HOME restores 6.00 mm standoff. |
| 5: Open for setup | Lift the guard if it is closed. An already open guard is confirmed automatically. | Mass changes require open access at zero speed. This also makes a restarted lesson usable when the previous run left the guard closed. |
| 6–8: Make a correction vector | Turn **Mass** by at least 0.050 g, turn **Angle** at least 20° with nonzero mass, then twist Mass back to 0.000 g. Release/regrip for additional turns as needed. | Mass sets the size of an added correction; angle sets its direction around the rotor. At zero mass, angle cannot create a force. The experiment starts with the bare rotor after this practice. |
| 9–13: Configure the experiment | Select **TWO-PLANE** with **MODE**, select B then A using **PLANE**, explore **SPEED** at 1500 rpm, then restore 1200 rpm. | Two separated correction planes can address both resultant force and rocking. Each plane affects both sensors. Selection changes which weight the dials edit; speed changes force and response. |
| 14–19: Practice safe operation | Lower and release the guard, start **SWEEP**, press **STOP**, wait for zero, then try **E-STOP**, **RECOVER**, and **HOME**. | The guard interlock and released handles are separate start prerequisites. STOP aborts partial data. E-stop latches and clears calibration; recovery never restarts the drive. This exercise happens before calibration. |
| 20–21: Read the baseline | Run **BASELINE** through acquisition, analysis, and coast-down; inspect the time trace, then press **CHART** for the order spectrum. | Taller waves/peaks mean greater displacement. An order of 1× means once per revolution, and 2× means twice. The measured response includes the support and sensor, rather than directly revealing a heavy-spot angle. |
| 22–25: Identify plane A | Open the guard, **FIT TRIAL** on A, close/release the guard, and **MEASURE TRIAL A** through coast-down. | A known 0.250 g change, compared with the original baseline at unchanged setup, reveals how A affects both measured channels. |
| 26–30: Identify plane B | Open the guard, select B, **FIT TRIAL**, close/release, and **MEASURE TRIAL B** through coast-down. | The helper restores A to baseline before adding B's known trial. Independent trials separate the effects needed for a two-plane solution. |
| 31–34: Install the prediction | **SOLVE**, inspect both predicted weights, open the guard, **APPLY CORRECTION**, then close/release. | The solver uses measured changes to predict cancellation. Apply replaces temporary trials with total installed weights. A prediction still needs measured evidence. |
| 35: Explore speed response | Complete **SWEEP** while watching its plot build, then wait for zero. | Speed-dependent force and support resonance shape a sweep. The curve does not replace a matched-speed balancing verification. |
| 36–38: Prove, repeat, and preserve | **VERIFY** at the 1200 rpm working speed, run **REPEAT** without edits, then **SAVE REPORT**. | A new verification tests the installed prediction. Repeats show scatter, while shared calibration errors do not average away. Finish with matched-speed evidence and preserve it in the report. |

The lesson targets the physical control used in each task. Mass and Angle refer to the selected correction plane; the physical micrometer is the sole probe adjustment. Menu navigation, comfort settings, motor sound, and visual preferences are independent conveniences, so the guide does not teach them as balancing operations. Deliberate sensor/tach fault injection remains available for independent diagnostics. Its effects require stopped recovery, a fresh reference, and new calibration; the core course teaches the recovery sequence using E-stop before taking valuable measurements.

## Automatic progression and voice

**Perform the task to advance.** The guide moves to the next instruction as soon as the accepted action and the task's physical completion conditions are satisfied. It does not wait for speech to finish. Entering the next step cancels the old recording and starts the matching explanation; recordings never queue or overlap. To hear the complete explanation, listen first and perform the action afterward.

Some tasks require more than pressing a cap. A held micrometer or dial must be released before another setup command, including HOME; the guard must be fully latched and released; a measurement must finish analysis and coast below 0.1 rpm. A run that merely started, was stopped early, or still has work on the analysis thread cannot satisfy a completed measurement. Existing measurements and old solutions do not silently complete new work.

**Right-stick click** replays the current explanation. Session offers **Voice ON/OFF** and **Replay Voice** separately from motor sonification. Voice preference persists in `user://narration.cfg`. Neither listening, replaying, nor muting can satisfy an instrument objective. The exact text and audio provenance are in [NARRATION.md](NARRATION.md) and `native/audio/tutorial/manifest.json`.

**X** reviews earlier instructions without moving the unfinished work checkpoint. **A** moves forward through review, or advances the current instruction only when its real objective is satisfied. Normal operation needs neither. **B/Y** opens the separate menu. The contextual prompt hides and narration pauses while that menu is open; closing it resumes the same audio position and finds a clear prompt location beside the target. Opening a menu does not stop an acquisition: keep the guard closed until zero speed.

Session retains **Pause/Resume**, **Restart Floating Guide**, **Skip Current Guide Lesson**, and **Guide at Startup ON/OFF**. Pause keeps the work checkpoint and cancels speech; resume restarts that instruction's explanation. Focus loss or invalid head tracking pauses audio in place. Restart preserves laboratory data but begins the instructional sequence again. Explicit Skip moves past an instruction without claiming its work occurred; skipping the final Save closes the guide without a successful-save completion record.

A successful final report ends the guide, records completion history, and turns startup OFF. Selecting startup ON later is honored. Pause and Skip do not change that preference. Current instruction, review position, and transient evidence are session-only; startup/completion history use `user://tutorial.cfg`. **New Session** resets the laboratory and clears obsolete guide evidence only after the real reset command succeeds. A rejected reset preserves work.

## Understanding the analyzer

The monitor uses real synthetic acquisition data, not decorative curves. Before the first capture, an explicit empty-state instruction explains how to obtain a trace. A run selects its relevant view: ordinary captures show a time waveform, and Sweep shows speed response. **CHART** cycles the available views for inspection.

- **Time:** displacement in micrometres against the captured time samples. The visible trace retains the last 256 samples of a 1,024-sample, 1,024 Hz record. Offset and noise remain visible.
- **Order:** the one-sided DFT frequency axis divided by that record's shaft frequency, displayed from 0–5× with 1× and 2× references. Vertical values are displacement peak micrometres. Finite-window leakage can spread a tone across bins, so the largest displayed bin need not equal the balancing amplitude.
- **Sweep:** once-per-turn displacement amplitude against rpm for successive quasi-steady windows. A curve appears as points are acquired. The support mode is 22 Hz (1320 rpm), but the apparent peak can shift because forcing grows with speed squared and samples have finite spacing. Peak height/width alone does not give damping from this unnormalized curve.

The solver uses a tachometer-referenced least-squares fit that separates offset, 1×, and 2×. It does not pick the tallest spectrum bin or read the generator's hidden unbalance. Vibration phase is timing relative to the shaft reference and includes the support response; it is not automatically the physical angle of the heavy spot. Near zero amplitude, phase becomes poorly observable.

## Measurement evidence and scientific scope

For one plane, a known trial `T` changes measured complex response from `V0` to `Vt`, identifying sensitivity `alpha = (Vt - V0) / T`. The correction is `C = -V0 / alpha`. In this course, two independent trials identify the two columns of a measured influence matrix; the solver finds two correction vectors together. The original baseline masses are retained in that calculation. Apply installs baseline plus correction, replacing temporary trials rather than adding a correction on top of them.

Baseline and both trials must have consistent speed, radius, probe geometry, and support response. Changing Home, probe position, speed, or mode invalidates calibration. If an accepted setup change, new baseline capture, E-stop, or fault invalidates calibration after baseline, the guide returns its work checkpoint to **Baseline**. It first points to stopped recovery and a fresh HOME if needed, then requires a new baseline and both new trial records. Historical records remain available. This recovery guidance does not press a control or clear a fault for the operator. Singular or insensitive trials must be corrected and measured again. Fresh Verify and Repeat must observe the calculated masses still installed at a matching setup. Low measured reduction is reported honestly rather than converted to a fabricated pass.

Three repeat windows report the mean, sample standard deviation, and Type A standard error `s / sqrt(n)`. Scatter describes observed consistency; these synthetic repeats omit shared calibration bias and do not establish total measurement uncertainty. The sweep evaluates separate quasi-steady synthetic records rather than integrating a real rotor's transient dynamics. [NATIVE_RESEARCH.md](NATIVE_RESEARCH.md) supplies equations, primary references, and the model's boundaries.

Accepted outcomes and record IDs are checked relative to each instruction's entry checkpoint. Fit Trial, Solve, Apply, and Save need accepted command outcomes plus their resulting state. Pre-validation contact telemetry, rejected commands, failed saves, and textual `"true"` values do not supply evidence. Actual report-file creation is required at the final task. The guide is an observer: it never mounts a rotor, presses a cap, changes a setting, runs a motor, saves a report, or clears a fault for the learner.

## Implementation and readability

`lab_tutorial.gd` independently observes snapshots and accepted outcomes. Its public API includes `start`, `observe`, `tick`, pure `view`, `next`, `back`, `skip_step`, `skip`, startup preference, and history. Rendering does not consume actions or move the work checkpoint. Ordered accepted actions can be preserved across a transition, while stale evidence and changes to the calibrated setup are rejected.

`tutorial_panel.gd` renders a read-only 0.24 × 0.10 m prompt with an arrow, short imperative, progress, and state. It has no collider or command dispatch. `target_callout_placement.gd` checks the complete prompt bounds and viewing clearance against current station geometry, avoids covering the target, and follows a moving guard or rotor. If all nearby candidates are blocked, the prompt hides while speech and target highlighting remain available. `tutorial_narrator.gd` plays one local recording at a time; narration never delays a valid task transition or operates the lab.

## Validation and headset feedback

Automated coverage should establish the complete numerical two-plane course, actual accepted actions, release/stopped gates, stale and aborted data rejection, chart data availability, invalid calibration handling, report creation, narration interruption/replay, preference isolation, and read-only presentation. Layout and collision tests complement these behavioral checks. Exact results for a release belong in [NATIVE_VALIDATION.md](NATIVE_VALIDATION.md).

The operator confirmed that v0.7.0's minimal prompts, spoken guidance, and small physical button markers were substantially better. That feedback also identified missing beginner explanation, unused micrometer, obscuring dial labels, and an empty graph; this expanded course and analyzer revision address those findings. Headless checks do not establish headset readability, voice pacing, comfort, or sustained frame performance. The revised 38-step lesson still needs a physical run. Setup and installation are in [APK_SETUP.md](APK_SETUP.md).
