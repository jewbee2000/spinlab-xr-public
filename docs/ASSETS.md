# SpinLab XR — asset manifest and visual model

Asset audit: 18 October 2026. The first demo uses original geometry generated by JavaScript, canvas-generated labels, and system fonts. It does not require downloaded CAD, textures, environment maps, photographs, audio, paid asset packs, or an external content service. These assets represent an invented engineering training bench.

## Native Quest controller assets

The native laboratory remains original procedural geometry. Its menu controller visuals now prefer the Quest runtime's device model and controller-driven hand mesh/poses. Runtime models are displayed in the app without exporting them into source control. This corrects hardware layout independently of the station scale or aim ray.

Thirty-eight neural narration clips are generated locally and bundled as Ogg audio in `native/audio/tutorial/`. Full transcripts, pinned model/voice hashes, audio hashes, codec metadata, and upstream licenses are retained beside them. See [narration provenance](NARRATION.md). No inference model or cloud service runs on Quest.

A pinned **Touch v3 / Quest 2** pair from the Immersive Web input profiles project is bundled as an MIT-licensed fallback. Exact commit, URLs, hashes, license, and transformations are recorded beside the assets in `native/assets/controllers/oculus-touch-v3/PROVENANCE.json` and `LICENSE.txt`. These are authored glTF controls rather than invented primitive layouts. Their min/max/value nodes drive button, trigger, grip, and stick animation. See [controller visuals](CONTROLLER_VISUALS.md) and [third-party notices](../THIRD_PARTY_NOTICES.md).

The rest of this inventory describes the original browser demo (version 0.1); native workspace geometry and interactions are documented in [UX_DESIGN.md](UX_DESIGN.md).

## Coordinates, size and materials

Three.js scene dimensions are metres, with positive Y up. The viewer starts in front of the station, looking along negative Z. The workbench is centered at `(0, 0, -1.4)`; its nominal worktop is at `Y = 0.85`. Its top measures approximately `1.80 × 1.12 m` in X/Z. The normal mounted rotor center is `(0, 1.00, -1.40)`, and the drawn rotor radius is `0.22 m`.

The guard hinge is at approximately `(0, 0.925, -1.75)`. Its closed frame is `0.68 m` wide, `0.70 m` deep and `0.46 m` high. The carriage's parent origin is `(0.46, 0.94, -1.4)`. The kit tray is left of the spindle, centered near `X = -0.63`.

The current immersive control panel is centered at `(-0.95, 1.31, -1.25)` and measures `0.66 × 0.82 m`. The live instrument panel is centered at `(0.95, 1.37, -1.25)` and measures `0.65 × 0.81 m`. The next-step display is centered at `(0, 1.98, -1.4)` and measures `1.32 × 0.19 m`. Three adjustment-knob centers are at `X = -0.24, 0, +0.24`, `Y = 0.98`, `Z = -0.84`. These are editable interface placements rather than fixture design dimensions.

The palette uses navy walls/floor, blue-gray metallic structural parts, cyan instrument accents and orange handles/adjustable features. Metal appearance comes from simple material color, roughness, metalness and static lights. There is no image-based environment, brushed-metal texture, ray-traced reflection, real-time shadow, or photographic lighting capture. The lid uses transparent material at low opacity rather than physical refraction.

The actual immersive reference space is `local-floor`. Head and controller poses come from WebXR; the desktop orbit camera is a review view. A world-height adjustment moves the station/UI together. In-headset reach, text legibility, occlusion, and seated/standing comfort still need physical Quest 2 verification.

## Deliberate visual exaggerations

These choices make the lesson readable. Geometry must not be used to infer the model's engineering dimensions.

| Item | Current visual treatment | Numerical model behavior |
| --- | --- | --- |
| Rotor speed | Mesh rotation is `0.022 ×` the indicated angular speed; at `1,800 rpm` it draws about `39.6 rpm` | Vibration calculations, displayed RPM, and exported measurements use the indicated speed |
| Probe travel | A `0–12 mm` setting maps to `96 mm` of displayed carriage travel, centered at `6 mm`: `(setting − 6) × 0.008 m` | Probe limits and the `5.5–6.5 mm` ready window use the actual setting |
| Correction location | Marker is drawn at `181 mm` radius on the enlarged rotor, approximately `6.03 ×` the model's correction radius | The balance equation uses the separately declared `30 mm` correction radius |
| Correction weight size | Foot width and brass-weight height increase for visibility; material appearance is illustrative | The entered grams determine the correction vector; mesh volume/density do not determine mass |
| Exploded view | Rotor moves up `0.29 m`; the shaft is stretched by `2.6 ×`; a guide and label appear | The training state and physical response calculation do not change |
| Vibration | Instruments show the synthetic response; the bench geometry remains steady | No rigid-body or flexible-body vibration solver drives the scene |
| Mounting and handling | A selection action moves the representation between tray and spindle | No collision, contact force, bolt torque, hand grasp, or cartridge insertion physics is modeled |
| Guard | Hinged motion is smoothed visually and the interlock has an immediate logical state | The guard is a training state input; the transparent cover has no collision/containment simulation |

The first version has no passthrough, tracked hands, eye tracking, photorealistic controller model, or audio assets. Its interaction baseline is tracked Touch-controller rays, trigger/grip actions, adjustment knobs, and optional haptic pulses. See [PROJECT_PLAN.md](PROJECT_PLAN.md) for later interaction work and [RESEARCH.md](RESEARCH.md) for the analytical assumptions.

## Geometry budget and verification

A CPU-only construction audit of `buildLab()` counted **79 mesh objects, 81 drawable objects, approximately 8,242 triangles including instanced copies, and 10 generated label textures**. This deliberately counts hidden optional geometry as well as the initial visible state. It is a structural estimate, not a measured Quest performance result. Transparent double-sided panels, stereo rendering, culling, hidden parts, and renderer behavior change the actual submitted draw calls.

`src/app.js` adds the immersive UI and controller rays. Its three adjustment knobs currently contain individual ridge meshes, so the world-space controls add substantially more draw calls than their triangle count suggests. The desktop overlay is HTML and does not add Three.js draw calls. Read the on-screen draw/FPS counter or `window.spinlab.getRenderStats()` during testing; record headset measurements in the acceptance record instead of substituting the structural estimate. The initial performance goal is sustained `72 Hz` on Quest 2, pending headset testing.

Syntax validation and CPU instantiation exercised rotor visibility, guard rotation, correction-marker movement, probe travel and exploded view. These checks do not verify binocular appearance, text clarity, controller mapping or real headset frame timing.

## Asset refinement workflow

The current runnable build needs no additional asset acquisition. After headset feedback, refine one assembly at a time in code or create an original low-detail CAD/Blender model from an invented drawing. Export a local glTF/GLB, preserve metre scale and origin/pivot conventions, reuse materials, merge static geometry where useful, and audit triangles, draw calls, texture sizes and source rights before replacing the procedural part. Keep the existing procedural version as a fallback.

For any future externally sourced asset, add its author, exact source URL, download date, license file, attribution requirement, modifications and bundled path to this manifest before incorporating it. Check scale, pivot conventions, and redistribution terms. Added assets should improve the learner's understanding of assembly or interaction while remaining readable at headset resolution.
